# ハッカソン技術セッション：包括的リサーチノート

**テーマ:** Google CloudとElasticを統合した次世代AIエージェントアーキテクチャの構築

## 1. アーキテクチャの全体像

本セッションで提示されたのは、「**Google Cloudの堅牢で自由度の高いエージェント開発環境**」と、「**Elasticsearchの極めて精度の高い検索・ログ基盤**」を組み合わせた最新のAIシステム構成です。データアクセスからUI（ユーザーインターフェース）のレンダリングに至るまで、エージェントが自律的かつシームレスに機能するための技術スタックが提供されています。

## 2. Google Cloud：エージェント開発エコシステム

Google Cloudでは、エージェントの作成からデプロイ、他システムとの連携までをカバーする新しいツール群が展開されています。

### ① Gemini Spark & Interactions API

* **事実確認・拡張:** **Interactions API**は、従来の `generateContent` APIを進化させた、エージェントワークフローのための新しい標準APIです。
* **特徴:** サーバーサイドでの状態管理や、複雑なマルチモーダル・マルチターンの会話に最適化されています。メモにある通り、長時間実行される非同期タスク（Deep Researchエージェントなど）を呼び出し、管理する上で不可欠なバックエンド基盤となります。

### ② Agents CLI & Agent Development Kit (ADK)

* **事実確認・拡張:** `uvx google-agents-cli` は実在するコマンドラインツールであり、インフラの構築からデプロイ、公開（Publish）までをサポートします。
* **特徴:** Agent Development Kit (ADK) を使用してPython等でエージェントを記述し、Agents CLIを通じてシームレスにデプロイします。CursorなどのAIコーディングエージェントと組み合わせることで、開発効率が劇的に向上します。

### ③ 実行環境の選択：Agent Runtime vs Cloud Run

* **Agent Runtime (Vertex AI Agent Engineなど):** エージェントに特化したフルマネージド環境。手軽に動かせる一方で、インフラレベルのカスタマイズ性（自由度）は制限されます。
* **Cloud Run:** コンテナベースの実行環境。メモにある通り、**A2UIなどの高度なプロトコルを利用してリッチな体験を提供するためには、自由度の高いCloud Runをデプロイ先として選択**することが推奨されます。

### ④ MCP Toolbox for Databases

* **事実確認・拡張:** Model Context Protocol (MCP) は、AIエージェントと外部データソースを繋ぐための標準プロトコルです。
* **特徴:** Googleが提供する「MCP Toolbox for Databases」は、Cloud SQLなどのエンタープライズDBとエージェントを直接かつ安全に接続するオープンソースサーバーです。これにより、エージェントが独自にSQLを発行して幅広いデータベースからリアルタイムに情報を引き出すことが可能になります。

## 3. 【深掘り】A2UIによるリッチUI体験の構築（最重要ポイント）

メモで指定されていた「**ADK ＋ Cloud Run ー (A2A ＋ A2UI) ＞ Gemini Enterprise → リッチなUI（天気カードなど）**」のフローについて、事実確認と詳細な技術解説を行います。

### 事実確認

このフローは事実であり、Googleの最新のエージェント間・エージェント-UI間プロトコルの根幹を成すものです。テキストだけでなく、視覚的なコンポーネントを返すエージェントを構築する上で最も重要な概念です。

### 技術詳細（情報の拡散）

1. **A2A (Agent-to-Agent):**
* プラットフォームやインフラに依存せず、エージェント同士が対話するための相互運用性プロトコルです。あるエージェントが別のエージェントを「サブエージェント」として呼び出す際などに使用され、アーキテクチャ全体の拡張性を担保します。


2. **A2UI (Agent-to-UI):**
* **概要:** AIエージェントに「テキスト」ではなく「実際のUIコンポーネント（カード、フォーム、チャート、テーブルなど）」を生成させるための技術です。
* **仕組み:** ADKで作成されたエージェントは、画面に何を表示すべきかを構造化されたJSON形式（A2UIペイロード）で出力します。それを受け取ったクライアント側（Gemini EnterpriseのフロントエンドやGoogle Chatアプリなど）のレンダラーが、そのJSONを解釈してネイティブなUIコンポーネントとして画面に描画します。
* **利点:** 開発者はクライアントごとのフロントエンド実装を気にすることなく、エージェントの「ロジック」と「出力すべきUIの構造」の定義（スキーマ定義）に集中できます。


3. **フローの全容:**
* 開発者が**ADK**でエージェントを書き、自由度の高い**Cloud Run**にデプロイする。
* エージェントは**A2A**プロトコルを通じて他のエージェントやシステム（DBなど）と連携し、ユーザーへの回答を生成。
* 回答の際、天気情報や株価チャートなどのリッチな情報が必要な場合、エージェントは**A2UI**のJSON形式で出力を行う。
* **Gemini Enterprise**などのクライアントがそれを受け取り、ユーザーに対してインタラクティブでリッチなUI（天気カードなど）を提示する。

## 4. Elastic Search：検索精度の極大化（RAGの高度化）

生成AIの回答精度は、プロンプトに与えるコンテキスト（検索結果）の質に直結します。Elasticsearchは、データやログを保存・解析するだけでなく、検索結果を最適化する強力なパイプラインを提供します。

### 検索精度を向上させる3つのアプローチ

1. **Query rescore (クエリ・リスコア):**
* **概要:** 最初の高速な検索（BM25など）で取得した上位のドキュメントセットに対して、Painlessスクリプトなどを用いて複雑なスコア計算を後から適用し、順位を再計算（リランキング）する手法です。
* **用途:** 鮮度（日付）や特定のビジネスロジックに基づくサイトスコアなどを加味して順位を微調整したい場合に有効です。


2. **Learning to Rank (LTR):**
* **概要:** ユーザーの過去の行動ログ（クリック数、アクセス結果、コンバージョンなど）を教師データとして機械学習モデル（XGBoostなど）を訓練し、そのモデルを使って検索結果を最適化する手法です。
* **用途:** ユーザーが実際に「良い」と判断した過去の傾向を検索スコアに反映させるため、ECサイトや社内ナレッジ検索などで絶大な効果を発揮します。


3. **Semantic Reranking (セマンティック・リランキング):**
* **概要:** Cohere等の強力なクロスエンコーダーモデル（LLM）を使用し、ユーザーの検索クエリとドキュメントの「意味的なつながり（文脈）」を深く理解した上で、最終的な検索順位を並び替えます。
* **用途:** キーワードの一致だけでは拾いきれない、ニュアンスを含んだ自然言語での質問（RAG向けのベクトル検索など）の精度を最終的に引き上げるための切り札として使用されます。

## 5. 発表資料化に向けたインサイト（まとめ）

ハッカソンでのアイディエーションや最終発表に向けて、この構成をどうビジネス価値に繋げるかが重要です。以下のストーリーラインでの発表をおすすめします。

* **課題:** 従来のチャットボットはテキストのみの単調なやり取りであり、かつ裏側のデータ検索精度が低いためハルシネーション（嘘）が多い。
* **解決策（データ側）:** **ElasticsearchのLTRとSemantic Reranking**を組み合わせることで、過去のログと意味的理解の双方から「最も確からしい事実データ」をエージェントに提供する。また、**MCP Toolbox**により社内DBとも直接連携させる。
* **解決策（UI側）:** **ADK + Cloud Run環境でA2UIを活用**し、単なるテキストチャットを脱却。ユーザーの状況に応じて、インタラクティブなダッシュボードやカード型UIをGeminiのインターフェース上に動的に生成し、圧倒的なユーザー体験を提供する。
